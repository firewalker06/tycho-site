## Source used for capture and audit

- Source archive: the GitHub tarball of tag `v0.14.1`, downloaded with `gh api repos/firewalker06/tycho/tarball/v0.14.1`. SHA-256 `9f0a4cc7066bf10a5c3e055c8483ed07d9c607361961ad84e6bc532394f34ccb`. It was extracted outside every checkout, to a temporary source directory.
- The archive's `Gemfile.lock` is identical to the product checkout's lock.
- `bin/tycho --version` reports `Tycho 0.14.1` from the archive.
- Runtime: Ruby 4.0.9. Gems come from the user's installed gem path, because a fresh `bundle install` failed to build the `erb` native extension in this Ruby install (`stdckdint.h` not found). The bundle check passed with that path.
- Isolation: `HOME` is set to a temporary directory. Config and logs are set through `TYCHO_CONFIG_PATH` and `TYCHO_LOGS_ROOT`. Without an explicit config path, subcommands printed the generic command list instead of their own help, so every help capture was taken with the config path pinned.

## Screenshot capture

The product tool `bin/capture-site-quickstart` was run from the archive. It starts a real Remote UI with synthetic fixtures (Atlas Web, Compass API, Beacon Mobile; nine agents). Chromium was Playwright's build, version 156.0.8078.4, at viewport 1440×900 with dark color scheme.

Two assertions in the tool did not match the default UI at this tag. They were changed in the archive copy only. The product checkout was not changed.

1. The watch step expected three `.agent-group` project groups. The default sort is `relevancy`, which renders one flat `.agent-group.agent-flat-list`. The check was changed to expect one flat group.
2. The watch step read the bounding box of `.agent-ledger`, which exists only in the grouped project view. It now reads `.agent-flat-list`.
3. The fit check required the list to end 24 to 96 px above the viewport bottom. The flat list ends 192 px above it, so the bottom-gap test was removed. The clipping and overflow checks remain.

These capture-tool defects are not site changes. They are logged in the product follow-up list below.

## CLI and help audit

- Source of truth: the command registration blocks in `lib/hq/cli_command.rb` at the tag. They register `harness list`; `project` (create, list, show, update, archive); `agent` (create, list, status, run, stop, logs, send, archive, finalize, clone, store with backups and restore, pr-diff with add and remove); `queue`; `queue-work` (complete, discard, process, remove); `memory handoffs`; `server` (login, logout, status, verify, migrate); `schedule` (create, update, validate, list, run, pause, resume, reload, restart); `debug claude`; `metrics` (query, backfill). `serve`, `serve restart`, `schedule daemon`, `update`, `doctor`, and `restart` are top-level forms.
- Counts, corrected. The earlier figures of "58 registered forms" and "58 invocations" are superseded.
  - **51 help invocations** were run with `ruby -I lib bin/tycho <command> --help`. These are 48 leaf or top-level forms with help output, plus 3 group forms: `agent store`, `agent pr-diff`, and `queue-work`. Exit status is 0 for all of them, except `restart`, which exits 64 because it is a deprecated alias that accepts no arguments.
  - **49 registered leaf forms** exist in source at the tag. 43 are registered inside `register` blocks in `lib/hq/cli_command.rb`. Six are top-level dispatch forms handled outside those blocks: `serve`, `serve restart`, `schedule daemon`, `restart`, `update`, and `doctor`.
  - Of those 49, `serve restart` is the one form whose `--help` output was not captured, because `--help` crashes with a `NameError`. It is a known released defect and is tracked separately from this site.
- `tycho serve restart --help` exits with `NameError: uninitialized constant HQ::CLICommand::RemoteCLIClient` at `lib/hq/cli_command.rb:1038`. An invalid option reports a normal error, and a remote call to an unknown server returns clean JSON. Only the help path fails.
- Every flag and subcommand the site reference documents was checked against the captured help. Changes made from that check are listed below.

## Product follow-up (outside this site PR)

1. `tycho serve restart --help` raises `NameError` at `lib/hq/cli_command.rb:1038`, because the rescue clause names `RemoteCLIClient` before the constant is loaded.
2. `bin/capture-site-quickstart` at the tag asserts the grouped project ledger (three groups, `.agent-ledger`, and a fitted list). The default relevancy view is a flat list, so the tool fails on the default UI. Logged for the product owner; not changed here.
3. The bundled `erb` gem failed to build with the Ruby 4.0.9 install in this environment (`stdckdint.h` not found). This does not affect the product, only this capture environment.
